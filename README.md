# Impact Blueprints

Сборка: Gradle 9.7.1 на JDK 25. Для Minecraft 1.7.10 также нужен установленный JDK 8.

```shell
git submodule update --init --recursive
./gradlew build
```

Параметры мода и публикации задаются в `impactMod` в `build.gradle.kts`.
Версия Forgelin переопределяется в каталоге `libs` в `settings.gradle.kts`.
ID мода — `iblueprints`, пакет — `space.impact.iblueprints`, имя Maven-артефакта — `ImpactBlueprints`.
Версия мода берётся из `RELEASE_VERSION`, затем `VERSION`, затем Git.
Для публикации используются `IMPACT_MAVEN_USER` и `IMPACT_MAVEN_PASSWORD`.

## Просмотр структур

Контроллеры автоматически берутся из `GregTech_API.METATILEENTITIES`: подключаются все
зарегистрированные метатайлы с `IConstructable`, включая добавленные другими модами.
Каталог собирается на `FMLLoadCompleteEvent`, после регистрации машин аддонами в post-init.
Открой рецепты или применения контроллера в NEI и вкладку «Структура».
Категория «Структура» одна. Панель катализаторов показывает контроллер, варианты блоков и хэтчей
из всех настроек каналов. «Применения» блока в NEI открывают подходящие структуры
с подсветкой мест установки в первой подходящей конфигурации. Клик по заголовку открывает весь каталог.
NEI показывает статическое превью, нарисованное движком. Клик по превью открывает
полноэкранный viewer на ModularUI2; Esc возвращает в NEI.

- ЛКМ с перетаскиванием — поворот, короткий клик — выбор блока.
- ПКМ с перетаскиванием — сдвиг, колесо — приближение перспективной камеры.
- Все / X–Y–Z / − / + / Срез — видимость слоёв; Сброс — камера по размеру сцены.
- Список справа показывает количество блоков сцены; клик выделяет блоки выбранного материала.
  Повторный клик снимает выделение. Выделение учитывает текущий слой.
- Наведение показывает название блока.

Сначала `construct` заполняет структуру корпусами и другими блоками в изолированном мире.
Если позиция допускает и корпус, и хэтч, показывается корпус. Survival-конструктор заполняет
только оставшиеся обязательные позиции, включая выделенные порты хэтчей.
Виртуальный источник блоков не обращается к инвентарю игрока.
Viewer показывает объявленные структурой каналы с их границами и нормализацией: изменение значения
перестраивает сцену и список материалов. Подсказка блока показывает его название.
В превью и viewer отображаются только блоки; пустые позиции не рисуются и не перехватывают выбор мышью.
По умолчанию показана полная форма, без среза и обводок. Предупреждения о сборке машины не выводятся:
сцена показывает геометрию структуры, а не автоматически собранную рабочую машину.
Метатайлы без `IConstructable` автоматически построить нельзя; для них нужен отдельный адаптер.
Захвата игрового мира, тиков механизмов и анимаций в MVP нет.

## API

Сцена создаётся на клиентском потоке через `BlockScene`, `ScenePosition` и `block(...)`.
Блок поддерживает metadata и необязательный NBT TileEntity. Координата Y — 0…255.
Собери сцену до создания `SceneView`; по окончании её использования вызови `close()`.

```kotlin
SceneRegistry.register(
    SceneEntry(
        id = "example:structure",
        item = ItemStack(Blocks.glass),
        factory = Supplier {
            BlockScene("Example").block(
                position = ScenePosition(
                    x = 0,
                    y = 64,
                    z = 0,
                ),
                block = Blocks.glass,
            )
        },
    ),
)
```

Свои сцены можно регистрировать в client post-init. Фабрика вызывается лениво на клиентском потоке при просмотре;
каждый вызов должен возвращать новую сцену. `SceneView` рисует сцену в заданном прямоугольнике
Minecraft GUI; `SceneWidget` подключает его к ModularUI2. Само ядро не зависит от NEI и ModularUI2.

Для группировки альтернатив в редакторе зарегистрируй правило `SceneAlternativeGroups.register` на клиенте.

```kotlin
SceneAlternativeGroups.register(
    translationKey = "example.alternatives.filters",
    matches = Predicate { stack ->
        stack.item === filterItem
    },
)
```

Ключ перевода определяет и подпись, и группу. Например, `iblueprints.variants.group.fluid_output`
добавляет предмет в группу вывода жидкостей. Первое подходящее правило аддона имеет приоритет
над стандартной группировкой. Варианты без группы попадают в «Остальные».

## Окружение разработки

После импорта/обновления Gradle запускай `runClient` из IDE или `./gradlew runClient`.
NEI, Angelica, ImpactStructures, GregTech IMPACT и ModularUI2 по умолчанию входят в dev runtime,
включая native launch-конфигурации RFG в IDEA. Обязательные для их запуска вспомогательные моды
перечислены явно в `build.gradle.kts`.

Интеграции используют `compileOnly` и `runtimeOnlyNonPublishable` с `isTransitive = false`.
Они не входят в Maven POM/Gradle metadata и не встраиваются в JAR движка. Наличие интеграций
проверяется перед загрузкой адаптеров. Без ModularUI2 остаётся доступно превью в NEI.

Для минимального запуска без интеграций:

```shell
./gradlew runClient -PsceneIntegrations=false -Pangelica=false
```

Тесты: `./gradlew test` (JUnit на JDK 8). Проверяются геометрия камеры, слои, границы сцены
и загрузка ядра без классов опциональных интеграций. Интеграционные проверки покрывают страницу NEI,
катализаторы, построение структур и регистрацию машин, добавленных в post-init.
